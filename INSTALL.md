# Установка на сервер

Пошагово: от чистого сервера до работающего ночного режима. Время: ~30–60 минут, большая часть —
скачивание моделей (~8 ГБ).

Сервер на Windows без Docker (например, Windows Server 2016 рядом с 1С) — **[INSTALL_WINDOWS.md](INSTALL_WINDOWS.md)**.

## 0. Что нужно

| | Минимум | Комфортно |
|---|---|---|
| ОС | Linux (Ubuntu 22.04/24.04, Debian 12) | |
| Процессор | 4 ядра | 8+ |
| Память | 16 ГБ | 32 ГБ |
| Диск | 30 ГБ свободно | 50 ГБ |
| Видеокарта | не нужна | NVIDIA 8+ ГБ — в разы быстрее |
| Сеть | доступ к АТС (веб-сервер записей), к github.com и к интернету на время установки | |

Понадобятся: логин/пароль к записям на АТС (лучше отдельная учётка только на чтение) и адрес сервера 1С,
с которого будут обращаться к сервису.

## 1. Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # перелогиниться, чтобы docker работал без sudo
sudo apt-get install -y make git
docker compose version             # должно показать v2.x
```

С видеокартой NVIDIA дополнительно: драйвер NVIDIA и
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

## 2. Код

Репозиторий приватный, поэтому нужен вход в GitHub:

```bash
sudo apt-get install -y gh         # или: https://cli.github.com
gh auth login                      # GitHub.com -> HTTPS -> вход через браузер по коду
gh repo clone qqsinka/call-transcriber
cd call-transcriber
```

Без GitHub на сервере: скачать архив кода (GitHub -> Code -> Download ZIP), скопировать на сервер
и распаковать.

## 3. Настройки

```bash
cp .env.example .env
chmod 600 .env                     # в файле пароли — читать только владельцу
nano .env
```

Обязательно поменять:

| Параметр | Что вписать |
|---|---|
| `AUTH_PASSWORD` | пароль к API сервиса (его же — в 1С) |
| `ATS_URL` | адрес записей на АТС, например `http://192.168.x.x:81/record` |
| `ATS_USER`, `ATS_PASSWORD` | учётка к записям на АТС |
| `ATS_LINES` | пусто — все папки за день; или линии через запятую, например `306090` |
| `ATS_FETCH_AT` | когда забирать записи, например `20:30` (после рабочего дня) |
| `ATS_LIVE_LINES` | линии в реальном времени, например `306090,687755`; пусто — только ночной режим (см. раздел 6.1) |
| `TZ` | часовой пояс, например `Europe/Moscow` — по нему работает расписание |

Хранение (можно оставить как есть):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `KEEP_AUDIO` | `false` | аудио удаляется сразу после успешной обработки |
| `AUDIO_RETENTION_DAYS` | `7` | аудио звонков с ошибкой хранится 7 дней для разбора, потом удаляется |
| `RESULTS_RETENTION_DAYS` | `0` | текст и саммари в базе хранятся всегда (число > 0 — столько дней) |

## 4. Запуск

```bash
make docker-up                     # CPU;  с видеокартой: make docker-up-gpu
make docker-logs                   # Ctrl+C — выйти из просмотра логов
```

Первый запуск долгий: сборка образа ~10 минут, затем скачиваются модели распознавания (~1 ГБ)
и LLM (~6.5 ГБ, видно в логах `ollama-pull`). Готово, когда:

```bash
make docker-status
```

показывает `"status": "ok"`, `"llm": {... "model_available": true}` и в `"ats"` — время `"next_fetch"`.

Если в логах `Permission denied` на `/app/data` или `/inbox` — у папок не тот владелец
(сервис в контейнере работает от пользователя с uid 1000):

```bash
sudo chown -R 1000:1000 data inbox && make docker-up
```

## 5. Проверка всей цепочки на 2 звонках

Не дожидаясь ночи: скачать пару записей с АТС и посмотреть, что они прошли весь путь.

**5.1. Доступ к АТС** — только список, ничего не скачивается:
```bash
make docker-fetch-ats DATE=2026-10-26 DRY=1
```
В конце строка вида `2026-10-26: папки 306090; к скачиванию 139, уже было 0, пустышек 8, ошибок 0`.
Ошибка `неверный логин или пароль` — проверить `ATS_USER`/`ATS_PASSWORD` в `.env`, затем `make docker-up`.

**5.2. Скачать 2 записи:**
```bash
make docker-fetch-ats DATE=2026-10-26 LIMIT=2
```

**5.3. Обработка** — в логах по каждому звонку `Из папки: … -> задача …`, затем `готово за … с`:
```bash
make docker-logs
```
На процессоре звонок в 2–3 минуты обрабатывается за 2–4 минуты (распознавание + эмоции + саммари).

**5.4. Результат** — по имени файла без `.mp3`:
```bash
curl -s -u transcriber:ПАРОЛЬ http://localhost:8000/jobs/26-10-26_09-02-47_79000000000_306090_1700000000.100000
```
Должны быть `"status": "done"`, фразы с таймкодами, `"emotion"`, `"summary"` с темой, приоритетом и тоном,
а также `phone`, `ext`, `call_date` из имени файла.

Проще — скрипт, который отправит тестовую запись и покажет итог:
```bash
python3 transcriber/scripts/checks/smoke_api.py samples/call_mono.mp3 --password ПАРОЛЬ
```

**5.5. Удаление аудио** — после обработки записей в папках нет, всё в базе:
```bash
ls inbox inbox/done                # пусто
du -sh data inbox                  # data — база (мегабайты), inbox — ~0
```

**5.6. Повторно не качает** — снова `make docker-fetch-ats DATE=2026-10-26 LIMIT=2`: эти два звонка
попадут в «уже было», скачаются следующие два.

## 6. Ночной режим

В `ATS_FETCH_AT` (например, 20:30) сервис сам:
1. забирает с АТС записи за сегодня и вчера (`ATS_FETCH_DAYS=2` — добирает поздние звонки);
2. пропускает пустышки и уже обработанные;
3. транскрибирует, считает эмоции и строит саммари — по очереди, до утра;
4. удаляет аудио после успешной обработки; раз в час убирает старое.

Утром проверить:
```bash
curl -s http://localhost:8000/health
```
`"ats": {"last_fetch_at": …, "last_fetch": ["2026-10-27: … скачано N …"]}` и `"queue": {"done": …}`
(если ещё идёт обработка — будут `queued`/`processing`).

Сколько успевает за ночь на процессоре: ~20–25 звонков в час (по замерам на 4-ядерном ПК),
т.е. ~150–200 звонков за 8 часов.
Больше — нужна видеокарта или второй запуск днём (`ATS_FETCH_AT=13:00,20:30`).

### 6.1. Реальное время для выбранных линий

Для линий из `ATS_LIVE_LINES` (например, входящие `306090,687755`) сервис каждые `ATS_LIVE_EVERY_MIN`
минут (по умолчанию 2) в часы `ATS_LIVE_HOURS` (по умолчанию 08:00–20:00) смотрит папку за сегодня
и сразу забирает новые записи: АТС кладёт файл после окончания разговора, поэтому звонок попадает
в обработку через 0–2 минуты после окончания, результат готов ещё через 2–4 минуты (на процессоре).
Ночной режим при этом работает как обычно и добирает всё, что днём могло не попасть.

Рекомендуемый порядок включения: сначала 1–2 ночи только ночной режим (раздел 5 и утренняя проверка),
затем `ATS_LIVE_LINES=306090` и `make docker-up`, после пары дней — добавить `687755`.

Проверка:
```bash
curl -s http://localhost:8000/health
```
в `"ats" -> "live"`: `last_poll_at` обновляется каждые 2 минуты, в `last_new` — последние скачанные записи,
`error` — `null` (иначе там причина: АТС недоступна, неверный пароль). В логах (`make docker-logs`) на каждый
новый звонок: `Загрузка с АТС …; скачано 1` → `Из папки: …` → `готово за … с`. Пустые проверки в лог не пишутся.

Нагрузка: ~15 входящих в час на процессоре — это ~40 минут работы в час, днём сервер загружен на 50–70%.
В пиковые часы очередь растёт и задержка до результата может быть 15–30 минут, потом очередь рассасывается.
С видеокартой — меньше минуты на звонок.

## 7. Обслуживание

| Задача | Команда |
|---|---|
| Состояние | `make docker-status` |
| Логи | `make docker-logs` |
| Перезапуск | `docker compose restart transcriber` |
| Остановить / запустить | `make docker-down` / `make docker-up` |
| Обновить версию | `git pull && make docker-up` |
| Резервная копия результатов | скопировать `data/jobs.db` (и `data/replacements.txt`) |
| Место на диске | `docker system df`, `du -sh data` |
| Тесты внутри контейнера | `make docker-test` |

Словарь автозамен `data/replacements.txt` правится на лету, перезапуск не нужен.

## 8. Безопасность

- Сменить `AUTH_PASSWORD`; `.env` — `chmod 600`.
- Открыть порт 8000 только серверу 1С, например:
  `sudo ufw allow from <IP сервера 1С> to any port 8000 && sudo ufw enable`
  (не забыть разрешить SSH: `sudo ufw allow ssh`).
- LLM (Ollama) наружу не публикуется, облачных сервисов нет — записи и тексты не покидают сервер.

## 9. Если что-то не так

| Симптом | Что проверить |
|---|---|
| `/health` долго `"starting"` | скачиваются модели — `make docker-logs` |
| `"model_available": false` | LLM ещё качается или не скачалась: `docker compose logs ollama-pull`, повторить `docker compose up -d ollama-pull` |
| АТС: `неверный логин или пароль` | `ATS_USER`/`ATS_PASSWORD` в `.env`, затем `make docker-up` |
| АТС: `АТС недоступна` | доступ с сервера: `curl -I http://адрес-АТС:81/record/` |
| Расписание срабатывает не в то время | `TZ` в `.env`, время в `/health` → `ats.next_fetch` |
| Реальное время не забирает звонки | `/health` → `ats.live`: `error` (причина), `last_poll_at` (идут ли проверки), часы `hours` |
| `Permission denied` на data/inbox | `sudo chown -R 1000:1000 data inbox` |
| Звонок со статусом `error` | текст ошибки в `/jobs/<id>`; аудио хранится `AUDIO_RETENTION_DAYS` дней в `inbox/done` |
| Нет места | `docker system prune` (удаляет неиспользуемые образы), `du -sh data inbox` |
